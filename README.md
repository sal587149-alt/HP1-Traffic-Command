# HP1 Traffic Command

واجهة عربية RTL لنظام إدارة المرور داخل سيرفر HP1. المشروع يستخدم Next.js + Supabase Auth + PostgreSQL/RLS.

## الوظائف الموجودة في هذه النسخة

- تسجيل دخول خاص بالبريد وكلمة المرور؛ لا يوجد تسجيل عام.
- إنشاء الحسابات من لوحة الإدارة عبر API خادمي يستخدم `SUPABASE_SERVICE_ROLE_KEY`.
- أدوار داخلية: عسكري، مشرف، ضابط، رئيس قسم، نائب مدير، مدير، عميد، مسؤول نظام.
- لوحة قيادة تعرض إحصاءات الحساب وآخر التقارير والتعاميم.
- إنشاء التقارير ومراجعتها واعتمادها أو رفضها مع ملاحظة.
- إنشاء الطلبات العسكرية وعرضها.
- دليل منسوبي المرور للمخولين.
- صفحات الترقيات والعمليات والتعاميم.
- سياسات Row Level Security أساسية في قاعدة البيانات.

> هذه قاعدة انطلاق وظيفية وليست منتجًا أمنيًا نهائيًا. صفحات إنشاء/تعديل العمليات والتعاميم والترقيات، المرفقات، الحجز الإداري، التنبيهات الفورية، ومراجعة الطلبات تحتاج استكمالًا قبل الاعتماد التشغيلي الكامل.

## 1) المتطلبات

- Node.js 20 أو أحدث
- حساب Supabase
- npm

## 2) إعداد قاعدة البيانات

1. أنشئ مشروعًا جديدًا في Supabase.
2. افتح **SQL Editor**.
3. شغّل كامل محتوى `supabase/schema.sql`.
4. من **Project Settings → API** خذ Project URL و`anon/public key` و`service_role key`.

## 3) إعداد المتغيرات

انسخ `.env.example` إلى `.env.local` ثم املأ القيم:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

**تحذير:** لا تضع `SUPABASE_SERVICE_ROLE_KEY` في أي متغير يبدأ بـ `NEXT_PUBLIC_`، ولا ترفع `.env.local` إلى GitHub أو ترسله لأحد.

## 4) التشغيل محليًا

```bash
npm install
npm run dev
```

افتح `http://localhost:3000`.

## 5) إنشاء أول مسؤول نظام

لأن التسجيل العام مغلق، أنشئ أول حساب يدويًا:

1. من Supabase **Authentication → Users → Add user**، أنشئ مستخدمًا ببريد وكلمة مرور قوية مع تفعيل تأكيد البريد.
2. انسخ UUID الخاص بالمستخدم.
3. في SQL Editor نفّذ الاستعلام التالي بعد استبدال القيم:

```sql
insert into public.profiles (id, full_name, email, rank_title, department, role, is_active)
values (
  'REPLACE-WITH-AUTH-USER-UUID',
  'مسؤول النظام',
  'admin@example.com',
  'مسؤول النظام',
  'الإدارة',
  'system_admin',
  true
);
```

4. سجّل الدخول من `/login`، ثم أنشئ الحسابات التالية من صفحة **إدارة الحسابات**.

لا تمنح دور `system_admin` إلا لشخص موثوق جدًا. يُسمح بإنشاء مسؤول نظام آخر فقط من حساب مسؤول نظام حالي.

## 6) النشر على Vercel

1. ارفع المشروع إلى مستودع Git خاص.
2. اربط المستودع بـ Vercel.
3. أضف متغيرات البيئة الأربعة في إعدادات المشروع.
4. انشر التطبيق.
5. حدّث `NEXT_PUBLIC_SITE_URL` إلى رابط الإنتاج.
6. اختبر الدخول وإنشاء الحسابات وRLS بأكثر من دور قبل دعوة المنسوبين.

## 7) ملاحظات أمنية قبل الاستخدام الحقيقي

- اختبر سياسات RLS عمليًا بحساب عسكري وحساب ضابط وحساب إدارة.
- في إصدار الإنتاج، أضف سجل تدقيق غير قابل للتعديل من العميل؛ لا تكتفِ بإدخال سجل من المتصفح.
- راجع سياسة تحديث التقارير؛ النسخة الحالية تسمح للمخولين بتحديث صف التقرير، ويُفضّل نقل اعتماد التقرير إلى API خادمي يتحقق من انتقال الحالة ويكتب المراجع ووقت المراجعة بشكل موثوق.
- أضف MFA للحسابات الإدارية، ومعدلًا لمحاولات الدخول، وتدويرًا لمفاتيح الخدمة عند الاشتباه بالتسريب.
- لا ترفع صورًا أو ملفات قبل إعداد Supabase Storage مع bucket خاص وسياسات وصول وحد أقصى للحجم وفحص نوع الملف.
- أضف اختبارات آلية واختبار اختراق قبل استخدام ملفات عسكرية حساسة.
- بيانات الموقع تجريبية/داخلية؛ لا يوجد اتصال تلقائي بسيرفر FiveM أو Discord في هذه النسخة.
